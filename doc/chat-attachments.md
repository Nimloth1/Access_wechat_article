# 聊天附件下载（试验版）

入口：双击项目根目录的 `start_chat_attachments.cmd`。

## 运行机制与两种路线

运行程序不调用 LLM、OCR 或外部识别接口，不消耗模型额度。它读取 Windows UI Automation 暴露的微信控件文字、类型和位置，用普通规则判断，再通过鼠标点击和滚轮操作。附件气泡定位会对内存中的局部截图做像素颜色采样，不识别图中文字。

v1.4 修复高缩放下误点发送者的问题：根据微信窗口 DPI 同步调整头像和昵称的排除区域，截图前激活目标窗口，点击前复核位置与缩放未变。旧版采用固定像素距离，在 200% 缩放下可能误入发送者窗口。更新后需关闭旧任务窗口并重新打开入口。

- **逐条聊天记录**：从当前位置向前扫描，按日期和外层消息数限制；打开图片再关闭，进入合并转发处理内部图片和文件。文件优先读取“未下载”标记，没有标记或明确下载按钮时直接跳过，不为这些文件逐个打开右键菜单。
- **连续图片上一张**：在最多 `max_messages` 条外层消息中找到第一张图片，打开后再点击最多 `previous_clicks` 次“上一张”，每张停留 `image_interval` 秒（默认 1 秒）。起始图片另计，即 100 次上一张最多产生 101 次预览机会。按钮不可用、用户停止或窗口核验失败时提前结束。该路线不处理文件和合并转发，也不筛日期；界面禁用这些设置，命令行/JSON 同时指定日期会报错。

连续图片模式记录的是预览打开和“上一张”点击次数，不能据此保证切换了多少张不同图片或确认原图下载完成。若预览出现明确的原图按钮，两种路线都会尝试点击。图片可能由微信在打开时自动加载，但没有界面完成证据时不会报告为已确认下载。

- 打开图片预览并返回父对话；识别了普通图片和 `ChatBubbleReferItemView` 图片。
- 打开一条含 4 条内部消息的转发记录，从底部逐条处理，再关闭返回。

- 完整任务处理 3 条外层消息和全部 4 条转发内部消息，确认两份文件已可用、打开 3 张图片预览，按外层上限停止，错误 0。日志为本机 `data/chat_attachments/20260908-112434-327138.jsonl`。

## 操作

1. 暂停本项目的公众号采集，在微信打开目标对话并滚动到希望开始的位置。
2. 保持 Windows 已解锁。启动附件操作窗口，保留默认的“启用兼容读取”，点击“检查微信”。若无法识别消息列表和对话标题，任务不能运行。
3. 对话名称留空使用当前对话，也可以每行填一个完整名称。搜索结果必须唯一，打开后再次核对标题。
4. 设置截止日期、消息条数和附件类型。默认 100 条、图片和文件、展开合并转发。
5. 默认勾选“仅扫描候选”，先确认扫描日志。取消勾选才会打开图片、展开转发或点击下载按钮。
6. 点击“开始”。点击“停止”或按 F9 取消。关闭操作窗口也会先停止任务并清理已打开的子窗口。

启动日志会明确提示当前是“仅扫描候选”还是“执行采集”。**勾选“展开合并转发”同时勾选“仅扫描候选”时，仍然不会进入转发。** 设置日期时，试扫描也会点击时间标签及滚动查找日期，但不操作附件。执行时每次进入转发都会打印“已进入合并转发”。

任务从对话**当前加载的位置**向前扫描，不自动跳到最新消息。指定其他对话时，从微信打开它后显示的位置开始。
任务会激活微信，并使用鼠标点击、滚轮和局部截图定位；运行时避免手动滚动、切换对话或调整窗口。局部截图仅用于内存中的定位，不作为生产日志保存。
远程桌面必须保持连接、解锁且展开显示；已连接但最小化时仍可能无法输入。当前不是可断开桌面运行的后台服务。
附件任务有独立运行锁，但该锁不覆盖已有的公众号采集流程，因此两者不能同时运行。

## 范围和计数

- 日期格式为 `YYYY-MM-DD`，例如 `2026-08-01` 表示向前扫描至 8 月 1 日，包含当天。
- 日期和数量任一边界先达到就停止。设置了日期时，条数可填 0 表示不限条数。
- “扫描条数”是外层消息总数，包括文字、图片、文件和合并转发卡片；时间分隔条不计数。
- 同页两个相同内容的消息分别计数。相邻页面靠有序重叠消息确认连续性，不用简单的内容集合去重。
- 合并转发卡片算一条外层消息，内部消息独立统计。默认最多展开 3 层，每个对话内全部转发合计最多处理 1,000 条内部消息。
- 日期筛选使用外层卡片发送日期，范围内的转发会处理其内部附件，不再按内部日期过滤。
- 日期标签支持完整年月日、今天、昨天、前天、微信星期标签和月日，以及已知日期下的时刻。星期按最近一次该星期归属，月日按最近一次该月日归属；正文日期不参与判断。独立时刻不能自动当作今天。
- 按日期运行时，自动点击可见的缩略时间行，例如把 `12:09` 展开为 `9月8日 星期二 12:09`，直接读取控件文字。当前页面最早消息缺少前置时间标签时，最多向前探查 80 次小幅滚轮，核验相邻消息重叠，找到日期后原路滚回；日期探查不消耗外层消息预算。
  返回时核验消息顺序和位置，只有完整内容与几何位置均恢复，才接受微信重建的控件实例。无法恢复原位置或点击后日期仍不可解析时停止。探查到边界仍无法确定日期的消息会跳过并记为 `unknown_date`，所以不能保证日期范围内附件齐全。
- 翻页后找不到重叠、重叠有歧义、消息布局重建导致身份无法核对，都会停止。外层滚动到顶部不直接等同于已读完全部历史。

## 下载行为与结果

图片：打开新图片预览窗口，寻找明确的“查看原图”等按钮。若存在则点击，等待完成状态，关闭该预览窗口并核对父对话。
没有原图按钮并不能证明原图已缓存；点击后按钮消失也不作为成功依据。

文件：优先使用气泡内明确的“下载”按钮。卡片明确显示“未下载”时，对 PDF、DOCX、XLSX、PPTX、TXT、CSV、ZIP、RAR、7Z 可单击触发微信接收；**微信可能在下载后自动用关联应用打开文件**，实测 PDF 会打开 Edge。程序、脚本、快捷方式不使用这个单击回退入口。若出现接收窗口，只操作文件名完全匹配的“接收文件”按钮，取消/退出时清理该文件的接收窗口。

没有“未下载”标记或明确下载按钮的文件直接记录为 `skipped_file`，不点击文件、不打开菜单；这表示按标记筛选跳过，并非已经核验本地缓存。大小和“未下载”在同一行时也能识别。
对需要下载的其他情况检查文件右键菜单：有明确“下载”才调用；原本已有“在文件夹中显示”时记录为 `available`，下载后出现才记录为 `confirmed`。找不到明确入口或完成证据则记为 `unconfirmed`。已可用文件不会再次单击打开。
合并转发：只接管本次点击产生的同进程 `mmui::RecordDetailWindow`，先滚动到内部列表底部，再倒序扫描，完成后关闭并返回父窗口。没有滚动接口时使用小幅滚轮，并核验消息重叠和位置；部分露出的气泡会先滚动到可操作位置。
如果微信复用了已有窗口、子窗口结构不同或无法核验返回，任务停止。

结果写入 `data/chat_attachments/*.jsonl`，逐条刷新，包含对话名、处理顺序、附件类型、状态和停止原因，不保存聊天正文。

| 状态 | 含义 |
| --- | --- |
| `candidate` | 只扫描到了候选，未执行下载 |
| `confirmed` | 界面出现明确下载完成状态，或下载后文件界面显示已可用；未做磁盘文件校验 |
| `available` | 文件界面原本已显示可用状态 |
| `skipped_file` | 无“未下载”标记或下载按钮，按筛选规则跳过；未核验缓存 |
| `unconfirmed` | 未找到明确下载入口，或无法确认完成 |
| `expired` | 界面报告过期或被清理 |
| `cancelled` | 用户停止 |

当前目标是触发微信自身缓存下载，没有复制成 JPG/PNG、按群导出、文件名归档或跨次运行断点续跑。
重新运行会重新扫描，当前去重只覆盖同次任务的相邻页面。

## 命令行与配置

以下命令在项目根目录执行：

```powershell
.venv/Scripts/python.exe chat_attachments.py --diagnose --compatibility
.venv/Scripts/python.exe chat_attachments.py --run --compatibility --max-messages 10 --dry-run
.venv/Scripts/python.exe chat_attachments.py --run --compatibility --chat "群 A" --chat "群 B" --since 2026-08-01 --max-messages 1000
.venv/Scripts/python.exe chat_attachments.py --run --compatibility --chat "180k拼团" --image-route viewer --previous-clicks 100 --image-interval 1 --max-messages 100
.venv/Scripts/python.exe chat_attachments.py --config doc/chat-attachments.example.json
```

`--config` 使用 JSON 文件作为完整任务设置；不要与其他任务参数混用。示例配置默认只扫描候选。
高级选项包括 `max_depth`、`max_forward_messages` 和 `download_timeout`，详见示例配置或 `--help`。

## 验证边界

自动化测试覆盖消息数、日期边界、重叠去重、相同内容消息、转发预算、层数限制、失败清理、取消、配置校验、控件日期归属、桌面不可交互时停止、长消息滚动、点击引起滚动后的衔接、有限转发起点、文件接收归属、程序文件不使用单击回退，以及兼容读取的版本限制和恢复。
这些测试不能替代微信真实界面验收。

v1.3 日期补全已在本机实测：点击时间行后读取 `9月8日 星期二 12:09`，向前探查后将“群聊的聊天记录”归属到 `2026-09-08`，返回原页并重新定位成功。无“未下载”标记文件已实测直接跳过。

v1.4 在 200% 缩放下实测进入用户反馈的合并转发，逐个打开其两张图片并返回群聊，错误 0；另一次从外层打开图片，完成 3 次“上一张”点击并关闭预览，错误 0。对应日志为 `20260908-165250-002433.jsonl` 和 `20260908-165342-396196.jsonl`。模拟回归覆盖 100%、150%、200% 缩放下头像/昵称颜色比附件更显著的情况，确保图片、文件、转发的点击候选仍在正文内。

同日按 `since=2026-09-01` 扫描 3 条外层消息和 2 条转发内部消息，打开 3 张图片，日期不明跳过 0、错误 0；按条数上限结束，日志为 `20260908-165438-595277.jsonl`。此短任务没有到达跨日期截止边界。

剩余实机验收：出现“查看原图”按钮的图片及其完成状态；多层嵌套转发；跨日期截止任务。日期探查的长任务验证曾因远程桌面无法提供可交互前台窗口而中断。不保证未知日期消息的附件齐全，建议首次使用先按少量条数运行。
